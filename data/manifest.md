## 파일 구조 및 스키마 (v2)

### 1. `sales.json` - 판매진척률 (판매채널별 상세 로그)

**집계 단위**: 제품(15개) × 일자(16일) × 채널(온라인/오프라인) = **480행**

**스키마** (플랫 배열):
```json
[
  {
    "date": "2026-09-01",
    "product": "아이폰18",
    "product_type": "Phone",
    "line": "A2",
    "channel": "온라인",
    "qty": 5200,
    "monthly_target_qty": 250000
  },
  {
    "date": "2026-09-01",
    "product": "아이폰18",
    "product_type": "Phone",
    "line": "A2",
    "channel": "오프라인",
    "qty": 3580,
    "monthly_target_qty": 250000
  },
  ...
]
```

**필드 설명**:
- `date` (str): 날짜 (YYYY-MM-DD)
- `product` (str): 제품명
- `product_type` (str): 제품종류 (Phone/Tablet/Watch/Automotive)
- `line` (str): 생산라인 (A2/A3/A4)
- `channel` (str): 판매채널 (온라인/오프라인)
- `qty` (int): 일일 판매실적 수량 (개)
- `monthly_target_qty` (int): 월간 판매목표 수량 (개)

**특징**:
- v1과 달리 각 제품의 일일 판매량을 온라인/오프라인으로 분리
- 채널별 비중은 제품마다 다르게 설정 (55~75% 온라인, 25~45% 오프라인)
- 날짜별로도 자연스러운 변동 반영
- 제품별 16일 누적 판매량은 v1과 동일하게 유지

### 2. `production.json` - 생산진척률 (생산교대별 상세 로그)

**집계 단위**: 제품(15개) × 일자(16일) × 교대조(주간/야간) = **480행**

**스키마** (플랫 배열):
```json
[
  {
    "date": "2026-09-01",
    "shift": "주간",
    "line": "A2",
    "product": "아이폰18",
    "product_type": "Phone",
    "qty": 1800
  },
  {
    "date": "2026-09-01",
    "shift": "야간",
    "line": "A2",
    "product": "아이폰18",
    "product_type": "Phone",
    "qty": 1450
  },
  ...
]
```

**필드 설명**:
- `date` (str): 날짜 (YYYY-MM-DD)
- `shift` (str): 교대조 (주간/야간)
- `line` (str): 생산라인 (A2/A3/A4)
- `product` (str): 제품명
- `product_type` (str): 제품종류 (Phone/Tablet/Watch/Automotive)
- `qty` (int): 교대별 생산실적 수량 (개)

**특징**:
- v1의 제품종류별 생산량을 제품 단위로 분해하고, 각 제품을 주간/야간으로 분리
- 각 제품이 속한 라인은 v1의 제품/라인 마스터 그대로 유지
- 제품종류별 16일 누적 생산량은 v1과 동일하게 유지
  - Phone: 492,299
  - Tablet: 151,170
  - Automotive: 13,919
  - Watch: 69,600
- 주간/야간 배분 비율은 일자별로 약간씩 변함 (50~60% 주간)

### 3. `capa.json` - CAPA 가동률 (라인별/교대별 생산 기록)

**집계 단위**: 라인(3개: A2/A3/A4) × 일자(16일) × 교대조(주간/야간) = **96행**

**스키마** (플랫 배열):
```json
[
  {
    "date": "2026-09-01",
    "shift": "주간",
    "line": "A2",
    "qty": 5500,
    "monthly_capa_qty_shift": 200000
  },
  {
    "date": "2026-09-01",
    "shift": "야간",
    "line": "A2",
    "qty": 4420,
    "monthly_capa_qty_shift": 200000
  },
  ...
]
```

**필드 설명**:
- `date` (str): 날짜 (YYYY-MM-DD)
- `shift` (str): 교대조 (주간/야간)
- `line` (str): 생산라인 (A2/A3/A4)
- `qty` (int): 해당 라인 교대별 일일 생산실적 수량 (개)
- `monthly_capa_qty_shift` (int): 월간 CAPA를 교대조별로 절반씩 배분 (개)

**계산식** (애플리케이션에서 수행):
- 라인별 가동률 = (16일 누적 생산량) ÷ (월간 CAPA) × 100%
- 이상 판정: 가동률 ≤ 90%

**특징**:
- v1과 달리 production.json을 라인별/교대별로 합산한 결과
- 따라서 production.json의 라인별 합계와 정확히 일치함 (정합성 보증)
- 월간 CAPA는 교대조별로 절반씩 배분 (예: A2 월간 400,000 → 주간 200,000, 야간 200,000)

### 4. `inventory.json` - 부진재고현황 (제품별 재고 로트 상세)

**집계 단위**: 제품(15개) × 로트(8~12개/제품) = **약 150행**

**스키마** (플랫 배열):
```json
[
  {
    "product": "아이폰18",
    "product_type": "Phone",
    "lot_id": "LOT-아이폰18-0001",
    "production_date": "2026-09-14",
    "remaining_qty": 320
  },
  {
    "product": "아이폰18",
    "product_type": "Phone",
    "lot_id": "LOT-아이폰18-0002",
    "production_date": "2026-08-10",
    "remaining_qty": 150
  },
  ...
]
```

**필드 설명**:
- `product` (str): 제품명
- `product_type` (str): 제품종류 (Phone/Tablet/Watch/Automotive)
- `lot_id` (str): 로트 ID (LOT-제품명-번호)
- `production_date` (str): 생산일자 (YYYY-MM-DD)
- `remaining_qty` (int): 미판매 잔여 수량 (개)

**부진재고 판정 기준** (애플리케이션에서 수행):
- 생산일자가 2026-07-19(기준일 기준 60일 초과) **이전**인 로트 → 부진재고
- 부진재고 비율 = (부진 로트 수량 합) ÷ (총 재고 수량) × 100%
- 이상 판정: 부진재고 비율 ≥ 5%

**특징**:
- v1과 달리 제품별 로트 수를 3~6개에서 **8~12개**로 확대
- 부진재고로 판정되는 8개 제품은 로트가 증가해도 부진재고 비율이 5% 이상 유지
- 정상 제품군은 부진재고 비율 5% 미만 유지

## v2 특징 및 활용

### 1. 더 자세한 로그 분석 가능
- 채널별 판매 트렌드 분석
- 교대조별 생산 효율성 분석
- 라인별 교대조 성과 비교

### 2. 이상징후 탐지 정확도 향상
- 채널별 수요 변화 감지
- 교대조별 생산 편차 감지
- 라인별 실시간 가동 모니터링

### 3. 시계열 데이터 풍부성
- 기존 1,000행 미만 → **1,200행 이상**
- 일별, 채널별, 교대별 세분화

### 4. 기존 이상 케이스 유지
- 판매/생산/CAPA/재고 이상 설계 동일 유지
- 새로운 로그 레벨에서도 검증 가능
- Biz Briefing Agent 테스트 케이스로 활용 가능

## 참고사항

1. **원본 수량만 포함**: 모든 파일에는 원본 수량 데이터만 포함
   - 진척률(%), 가동률(%), 부진재고 비율(%) 등 계산값은 미포함
   - 애플리케이션 로직에서 계산 (데이터-로직 분리 원칙)

2. **인코딩**: UTF-8 (한글 지원)

3. **정합성 확보**:
   - sales.json 제품별 일일 합계 = v1 원본 유지
   - production.json 제품종류별 합계 = v1 원본 유지
   - capa.json 라인별 합계 = production.json 라인별 합계 자동 일치
   - inventory.json 부진재고 비율 = v1 목표 유지

4. **CSV와 JSON**: 동일한 데이터, 다른 포맷 (선택적 사용)
