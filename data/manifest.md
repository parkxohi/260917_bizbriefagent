## 파일 구조 및 스키마

### 1. `sales.json` - 판매진척률 (제품별)

**집계 단위**: 제품(15개) × 일자(16일)

**스키마**:
```json
[
  {
    "product": "아이폰18",
    "product_type": "Phone",
    "line": "A2",
    "monthly_target_qty": 250000,
    "daily": [
      {"date": "2026-09-01", "qty": 7800},
      {"date": "2026-09-02", "qty": 8200},
      ...
    ]
  },
  ...
]
```

**필드 설명**:
- `product` (str): 제품명
- `product_type` (str): 제품종류 (Phone/Tablet/Watch/Automotive)
- `line` (str): 생산라인 (A2/A3/A4)
- `monthly_target_qty` (int): 월간 판매목표 수량 (개)
- `daily` (array): 일자별 판매실적
  - `date` (str): 날짜 (YYYY-MM-DD)
  - `qty` (int): 일일 판매실적 수량 (개)

**특징**:
- 월간 판매목표는 제품 특성에 맞게 설정 (폰/태블릿 대량, Automotive/Watch 소량)
- 일별 수량은 평일/주말 변동, 자연스러운 등락 반영
- **총 240건** (15 products × 16 days)

---

### 2. `production.json` - 생산진척률 (제품종류별)

**집계 단위**: 제품종류(4개) × 일자(16일)

**스키마**:
```json
[
  {
    "product_type": "Phone",
    "monthly_target_qty": 900000,
    "daily": [
      {"date": "2026-09-01", "qty": 28000},
      {"date": "2026-09-02", "qty": 29500},
      ...
    ]
  },
  ...
]
```

**필드 설명**:
- `product_type` (str): 제품종류 (Phone/Tablet/Watch/Automotive)
- `monthly_target_qty` (int): 월간 생산목표 수량 (개)
- `daily` (array): 일자별 생산실적
  - `date` (str): 날짜 (YYYY-MM-DD)
  - `qty` (int): 일일 생산실적 수량 (개)

**특징**:
- 제품종류별로 월간 생산능력 목표 설정
- 패널 기준이므로 개별 제품이 아니라 제품종류 레벨
- **총 64건** (4 product_types × 16 days)

---

### 3. `capa.json` - CAPA 가동률 (라인별)

**집계 단위**: 라인(3개: A2/A3/A4) × 일자(16일)

**스키마**:
```json
[
  {
    "line": "A2",
    "monthly_capa_qty": 400000,
    "daily": [
      {"date": "2026-09-01", "qty": 11000},
      {"date": "2026-09-02", "qty": 11500},
      ...
    ]
  },
  ...
]
```

**필드 설명**:
- `line` (str): 생산라인 (A2/A3/A4)
- `monthly_capa_qty` (int): 월간 CAPA(생산능력) 수량 (개)
- `daily` (array): 일자별 생산실적 수량 (해당 라인의 누적)
  - `date` (str): 날짜 (YYYY-MM-DD)
  - `qty` (int): 일일 생산실적 수량 (개)

**계산식** (애플리케이션에서 수행):
- 가동률 = (16일 누적 생산량) ÷ (월간 CAPA) × 100%
- 이상 판정: 가동률 ≤ 90%

**특징**:
- 라인 매핑에 따라 해당 제품종류들의 생산량을 합산
- production.json의 데이터와 정합성 유지
- **총 48건** (3 lines × 16 days)

---

### 4. `inventory.json` - 부진재고현황 (제품별 로트)

**집계 단위**: 제품(15개)별 재고 로트 스냅샷 (기준일: 2026-09-17)

**스키마**:
```json
[
  {
    "product": "아이폰18",
    "lots": [
      {"production_date": "2026-09-10", "remaining_qty": 320},
      {"production_date": "2026-08-20", "remaining_qty": 150},
      {"production_date": "2026-06-01", "remaining_qty": 80},
      ...
    ]
  },
  ...
]
```

**필드 설명**:
- `product` (str): 제품명
- `lots` (array): 재고 로트 목록
  - `production_date` (str): 생산일자 (YYYY-MM-DD)
  - `remaining_qty` (int): 미판매 잔여 수량 (개)

**부진재고 판정 기준** (애플리케이션에서 수행):
- 생산일자가 2026-07-19(기준일 기준 60일 초과) **이전**인 로트 → 부진재고
- 부진재고 비율 = (부진 로트 수량 합) ÷ (총 재고 수량) × 100%
- 이상 판정: 부진재고 비율 ≥ 5%

**특징**:
- 제품별 3~6개 로트로 구성
- 최근/중간/오래된 로트를 자연스럽게 혼합
- **총 58개 로트** (평균 3.87개/제품)

2. **git 관리 대상 아님**: 이 파일들은 개발 단계 테스트용 샘플 데이터이므로
   - 메인 세션에서 처리 후 `git add/commit` 여부를 결정

3. **정합성 확보**: 
   - production.json의 제품종류별 생산량을 라인 매핑에 따라 분배하여 capa.json과 연계

## 이상 케이스 활용

Biz Briefing 이메일 발송 로직이나 대시보드 화면 개발 시:

1. **판매/생산 이상 검출**: 표준진척률(53.3%) 대비 ±5%p 벗어난 제품/제품종류 조회
2. **CAPA 이상 검출**: 라인별 가동률 90% 이하인 라인 조회
3. **부진재고 이상 검출**: 부진재고 비율 5% 이상인 제품 조회
4. **우선순위 분류**: 심각도에 따라 대시보드 알림/이메일 우선순위 결정

이러한 케이스들이 제대로 잡혀나오는지 검증함으로써 이슈 선별 로직의 정확성을 확인할 수 있습니다.
